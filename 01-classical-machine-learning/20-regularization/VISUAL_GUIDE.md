# Day 20 Regularization Visual Lab

Run [day20_regularization_visuals.py](day20_regularization_visuals.py) to compute
and render thirteen views. The numerical experiments live in
[visual_math.py](visual_math.py), separately from rendering, and are checked by
[tests/test_visual_math.py](tests/test_visual_math.py). All datasets are
synthetic and generated locally. No server, notebook, credentials, dataset
download, Streamlit, or Dash is required.

## Run locally

Use the repository's existing environment and canonical
[pyproject.toml](../../pyproject.toml):

```bash
python -m pip install -e ".[dev]"
python 01-classical-machine-learning/20-regularization/day20_regularization_visuals.py
```

For generation without plot windows, including VS Code terminal use:

```bash
python 01-classical-machine-learning/20-regularization/day20_regularization_visuals.py --no-show
python -m pytest -q 01-classical-machine-learning/20-regularization/tests
```

The runtime libraries used by this lab are NumPy, scikit-learn, Matplotlib,
SciPy (for the constraint-boundary root solve), and Pillow. Plotly is optional
and adds an offline, rotatable HTML surface with an alpha slider. The
repository's shared dependency configuration includes all of them.

Top-of-file settings expose `RANDOM_STATE`, `OUTPUT_DIR`, `SHOW_PLOTS`,
`SAVE_PLOTS`, repeat count, frame count, DPI, and GIF speed. Defaults use seed
42, 100 repetitions (60 for grouping), 48 frames, and eight GIF frames per
second. The default output directory is relative to the script, so running
from another working directory produces the same output location.

Supported options:

```bash
python 01-classical-machine-learning/20-regularization/day20_regularization_visuals.py --no-show --repeats 50 --frames 40
python 01-classical-machine-learning/20-regularization/day20_regularization_visuals.py --no-show --output-dir path/to/outputs
python 01-classical-machine-learning/20-regularization/day20_regularization_visuals.py --no-show --matplotlib-3d
```

`--no-save` computes the views without saving files; combine it with the normal
interactive Matplotlib mode to study the figures on screen. The offline HTML
is written when saving is enabled; open it manually in a browser. Its slider
recomputes the displayed frame's surfaces and optima from precomputed data.
Rotation, zoom, and hover are available without network access. Plotly's
JavaScript is embedded, so the HTML is larger than the PNGs.

## Conventions that matter

All penalty paths, surfaces, and fixed-alpha simulations use

\[
\frac{1}{2n}\|y-b-Xw\|^2
+\alpha\rho\|w\|_1+\frac{\alpha(1-\rho)}2\|w\|^2.
\]

Ridge calls use native `alpha = n_train * normalized_alpha`. Lasso and
ElasticNet use the normalized alpha directly. The polynomial prediction
comparison instead searches **native Ridge alpha**, explicitly labeled in
its panels and console output. The intercept is never penalized.

The constraint panel uses an L2 radius of one and an L1 budget of one. These
are different feasible sets, not equal-strength penalties. Their optima are
found from the quadratic problem; the highlighted contours go through those
computed optima.

The coefficient paths use one fixed training-fitted scaler to hold the
representation constant. Other experiments re-fit scaling within each
training sample, bootstrap, or CV fold. Scaled coefficients measure target
change per training standard deviation. The collinearity panel converts
coefficients back to raw units; the scaling panel also reports unit-adjusted
effects so tiny raw coefficients are not mistaken for tiny contributions.

Soft thresholding directly solves Lasso under an orthonormal design. For
correlated designs, it is part of an iterative solver. Neither Ridge's
individual coefficients nor Lasso's active set must change monotonically.
The all-zero Lasso threshold is computed from centered correlations; beyond
that threshold all coefficients are zero.

Bias and variance are estimated from fresh training samples and evaluated
on a common fixed grid against a known mean function. Variance uses `ddof=0`,
so the finite Monte Carlo identity between squared bias plus variance and
mean squared error against the true function holds numerically. Known noise
variance is then added to estimate noisy-target risk. These remain finite
Monte Carlo estimates, and their minimum is not a cross-validated parameter.

The grouping and Lasso stability experiments use paired bootstrap samples
at fixed illustrative penalties, without alpha tuning. In contrast, the
middle polynomial fit uses five-fold CV with polynomial features and scaling
inside the searched pipeline. It is called “CV-selected,” not universally
optimal. Polynomial panels use different y scales so the weak-penalty
excursions remain visible without flattening the other curves.

## Observed results and interpretation candidates

The default experiments were executed using seed 42, Python 3.11.0rc2,
NumPy 2.4.6, scikit-learn 1.9.0, Matplotlib 3.11.0, and Pillow 12.3.0.
The JSON record is regenerated by every run and includes the full grids and
sample counts. Results below are synthetic observations; interpretations
require author review.

- **Geometry:** the constrained Ridge optimum was approximately (0.9355,
  0.3533), while the L1 optimum was (1, 0). Candidate interpretation: the
  L1 corner explains the zero second coordinate in this constructed problem.
- **Bias/variance:** the minimum estimated noisy-target MSE on the grid was
  about 0.5600 at normalized alpha 0.13895, compared with 13.6345 at the
  weakest penalty and 1.0913 at the strongest. Candidate interpretation:
  shrinkage reduced unstable polynomial predictions enough to offset bias.
  The empirical squared-bias curve was not monotone, so the figure does not
  force the textbook shape.
- **Collinearity:** at proxy-noise SD 0.01, OLS coefficient SDs were about
  (12.243, 12.234), versus (0.0523, 0.0513) for Ridge. Mean reference RMSEs
  were about 1.0195 and 1.0126. Candidate interpretation: coefficient
  uncertainty and prediction error convey different information.
- **Lasso stability:** x1 was retained in 97% of bootstrap fits, x2 in 76%;
  only x1, only x2, and both appeared in 24%, 3%, and 73%. Candidate
  interpretation: sparsity does not guarantee a unique stable explanation.
  These are conditional bootstrap frequencies, not population probabilities.
- **Grouping:** all three correlated features were retained in 100% of
  fits at ratio 0.5, versus about 8.3% for pure Lasso at the fixed alpha
  0.15. Candidate interpretation: the L2 component encouraged shared
  representation here; this does not establish support recovery.
- **Polynomial prediction:** CV selected native Ridge alpha about 0.372759.
  Function RMSEs for weak, selected, and strong penalties were about 8.326,
  0.216, and 0.853. The separate selection CV RMSE was about 0.483.
  Known-function error is not a held-out noisy-target benchmark.
- **Scaling:** effective weights without scaling were about (1.054, 1.916),
  versus (0.962, 0.955) after scaling, against true latent effects (2, 2).
  Reference RMSE increased from about 1.074 to 1.522 at the fixed normalized
  alpha 1. Candidate interpretation: scaling removed the unit-driven penalty
  imbalance, but equalizing shrinkage at an untuned penalty did not improve
  prediction error. Tune after choosing the representation.

These experiments do not establish universal estimator rankings. They use
bounded synthetic distributions, finite grids, and finite resampling. No
causal interpretation or scientific feature-selection claim follows from a
zero coefficient.

## Three views to study first

1. **Geometry (01):** links the optimization constraint to an exact zero.
2. **Soft thresholding (04):** turns the L1 mechanism into a concrete operation.
3. **Multicollinearity (06):** separates coefficient stability from predictive
   accuracy, a useful distinction in senior model-review discussions.

The bias/variance panel (05) is the next step for understanding why shrinkage
can help. Geometry and the soft-threshold GIF are candidates for a later,
small public preview set. No LinkedIn draft or publication action is included.
