# Study Context

## Personal and Professional Context

I am a Senior Data Scientist / Applied AI Engineer based in Brazil. I work with real-world AI systems and want to strengthen my theoretical foundations while improving my public technical portfolio.

My professional experience includes:

- Data Science and Applied AI;
- Generative AI applications;
- Retrieval-Augmented Generation;
- conversational agents;
- document intelligence;
- OCR and summarization workflows;
- Google Cloud Platform;
- Vertex AI;
- BigQuery;
- Cloud Run;
- Cloud Functions;
- Document AI;
- Gemini models;
- Python and SQL;
- production-oriented data and AI systems.

I am looking for new opportunities and have been doing several interviews. Many interviews are theoretical, so I want to study consistently for 30–60 minutes per day to become stronger in both concepts and practice.

## Target Positions

The study path should prepare me for interviews and practical expectations in roles such as:

- Senior Data Scientist;
- Machine Learning Engineer;
- Applied AI Engineer;
- AI Engineer;
- GenAI Engineer;
- Forward Deployed Engineer;
- LLM Engineer;
- AI Solutions Architect.

## Main Objective

The goal is to become senior not only in practical delivery, but also in conceptual understanding.

For each topic, I want to be able to:

1. explain the intuition clearly;
2. describe the theory and mathematics behind it;
3. implement a simple version when possible;
4. use the right libraries and tools in practical examples;
5. identify trade-offs and limitations;
6. answer interview questions confidently;
7. connect the topic to real-world AI systems;
8. document the result in a professional GitHub repository.

## Study Time Constraint

The daily study block should fit into approximately:

```text
30–60 minutes per day
```

Some topics may require more than one day. It is acceptable to split complex topics into multiple sessions when needed.

## Expected Depth

Do not explain topics as if I were a complete beginner.

Assume I already work in the field and have practical experience. The goal is to consolidate senior-level understanding.

The ideal explanation should be:

- clear;
- rigorous;
- interview-oriented;
- practical;
- connected to real production trade-offs;
- not superficial;
- not unnecessarily academic.

## Preferred Study Format

Each topic should include:

1. Executive overview
2. Intuition
3. Theoretical foundations
4. Mathematical/statistical/logical foundations
5. Practical applicability
6. Common mistakes and pitfalls
7. Comparisons with related approaches
8. Python example
9. From-scratch implementation when useful
10. Suggested experiments
11. Senior interview questions and answers
12. Short interview-ready explanation
13. GitHub file structure
14. README content in English
15. LinkedIn post idea in Portuguese
16. 30–60 minute execution checklist

## Repository Philosophy

The repository should not look like a random dump of study notes.

It should look like a professional Applied AI Engineering lab, showing that I can:

- understand fundamentals;
- implement concepts;
- evaluate models and systems;
- think about production constraints;
- explain design decisions;
- communicate technical trade-offs.

## LinkedIn Strategy

LinkedIn should not become a daily study diary.

The strategy is:

- study and commit daily when possible;
- post on LinkedIn around 2 times per week;
- share insights, not long mathematical notes;
- keep deep technical details in GitHub;
- use LinkedIn as a professional visibility and positioning channel.

## Tone for Study Content

The content should be written in a technical but accessible tone.

For GitHub:

- README files should preferably be in English;
- deep notes can be in English or Portuguese depending on the study purpose;
- code comments should be clear and professional.

For LinkedIn:

- posts should be in Portuguese;
- tone should be natural, professional and not exaggerated;
- avoid sounding like self-help or generic AI hype;
- focus on concrete technical insight.

## What Good Looks Like

A good daily output should allow me to say:

> I understand this topic well enough to explain it in a senior interview, implement a simplified example, discuss trade-offs and connect it to production AI systems.

A good GitHub folder should allow someone else to quickly see:

- what the topic is;
- why it matters;
- how it works;
- how to run the code;
- what questions might be asked in interviews;
- what practical limitations exist.
